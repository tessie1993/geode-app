# Geode's sound engine

Geode's visuals are only as good as what they hear. Two separate paths carry sound and they must not be confused:

1. **Playback chain** (Kotlin, Media3): ExoPlayer runs `MvzAudioProcessorChain` on its playback thread. `PcmTap` is first, before any DSP, so DSP never moves the visuals. Two rules never bend: the tap stays first, and the chain never gets float output. What the sink then plays the PCM through is below the chain and changes neither: an AudioTrack, or the native Oboe output (`core/audio/output`, `audio/OboeAudioOutput`) when Settings › Playback has it on.
2. **Sound engine** (C++, `core/sound`, the `geode_sound` library over `geode_pcm`; `tools/sound-module-gate.sh` holds its includes): live, one analysis thread per PCM ring (`core/sound/hop/AnalysisThread`) reads the ring's new PCM and every 10 ms of samples runs one analysis hop (FFT, filter bank, drums, melody, Rhythm, Harmony, Form, Emotion), publishing it (`core/sound/hop/SharedAnalysis.hpp`); an export runs the same engine inline. A renderer only reads the newest published hop each frame (`Renderer::readSound`, `core/viz/RendererFrame.cpp`) into a `GeodeSoundFrame` (triggers held since the last read, beat phases moved to the frame's sample) (`core/sound/SoundFrame.h`). Styles read it through `lib_sound`.

## Where things are

| Need | Open |
|---|---|
| Spectrum, bands, FFT | `core/sound/Fft.*`, `FilterBank.hpp`, `Stages.hpp` |
| Transients: the sharp start of any sound, per sample | `core/sound/Transient.hpp` (test: `core/tests/transient_test.cpp`) |
| Tempo, beat, bar, phrase (on the engine's 10 ms hop) | `core/sound/Rhythm.*` |
| Chroma, key, chord, tension, scale | `core/sound/Harmony.*`, `ScaleTable.inc` (generated by `tools/musical_intelligence.py` from `docs/musical-intelligence/`) |
| Novelty, sections, build-up, drop | `core/sound/Form.*` |
| Valence, energy, tension, GEMS-9 | `core/sound/Emotion.*`, `EmotionTable.inc` (generated by `tools/music_emotion.py`) |
| Rest-when-silent (wallpaper, dream) | `core/sound/Silence.hpp` |
| Export resampler and BS.1770 meter | `core/audio/dsp/PcmResampler.*`, `Loudness.*` |

## Rules

- Engine logic lives in C++. Kotlin only feeds samples and reads results.
- No bias on BPM, ever (owner's rule; `tools/no-bpm-bias-gate.sh` and `musical_test` fail the PR). `Rhythm` scores every lag in its search range alike and takes the fastest one about as periodic as the strongest; nothing prefers, weights or centres on a tempo, and until one is heard there is none (`bpm` 0, no beats, no ticks; consumers run in seconds). Do not port a tempo weighting curve or a start tempo from Ellis, librosa, aubio or any paper, however standard: that is how the bias came back four times.
- Export must equal live: the export job (`core/output/ExportFrame`) steps its own engine at 1/fps from `core/audio/ingest/TrackPump`. Analysis runs per hop with the hop's dt, never the frame's; `core/tests/sound_rate_test.cpp` fails if 30 or 120 fps differ from 60 at a shared sample.
- Never edit `ScaleTable.inc` or `EmotionTable.inc` by hand: change the CSV or the generator and regenerate.
- A new `GeodeSoundFrame` value is also a new `ReactSource`. Update the reaction DNA (`core/viz/ReactionDna`) and the wire layouts `core/tests/mod_document_test.cpp` checks.

## Prove it on the host (no device, no Gradle)

```sh
g++ -std=c++20 -O1 -Wall -Wextra -Icore core/tests/sound_test.cpp core/sound/*.cpp -o /tmp/sound_test && /tmp/sound_test
g++ -std=c++20 -O1 -Wall -Wextra -Icore core/tests/musical_test.cpp core/sound/*.cpp -o /tmp/musical_test && /tmp/musical_test
```

`.github/workflows/native-host-tests.yml` has the exact line for every other native test (director, note response, resampler, loudness). Write the test first: the engine is pure C++, so every detector can be driven with synthetic PCM (clicks for beats, sines for chroma, silence for `Silence`).
