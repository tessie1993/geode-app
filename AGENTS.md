# AGENTS.md: MuzViz Studio Pro (internal name Geode)

Android music player, reactive visualizer and video studio. Kotlin and Compose with Hilt, plus a C++20 native core (`libgeode.so`).
applicationId `com.muzviz.studiopro`. Kotlin packages stay `dev.geode.*`. minSdk 33 (Android 13+), targetSdk 36, compileSdk 37.

## Owner's hard rule: Kotlin is the shell, C++ is the app (read first)

- **Kotlin only for the main-thread shell**: Compose screens, ViewModels, Android services and platform APIs, stores, and the JNI declarations in `GeodeNative`. It draws what native says and hands values across. It decides nothing about a parameter, a sound or a picture.
- **Everything inside is C++ (`core/`), never Kotlin**: all logic off the main thread, all parameter code (rolls, resets, which control is where, modulation, LFOs, envelopes, reactions), the audio engine and DSP, shaders and the renderer, every engine internal. That includes "small" helpers and tables: if it computes or decides, it is C++, with a host test in `core/tests/`.
- **Why:** one implementation for live, wallpaper, dream and export (no Kotlin copy to drift), testable on the host without a device, and the GL and audio threads never wait on the JVM. ADR `0003` is the plan. Any Kotlin engine code still left is debt to port, never a pattern to copy. If you are about to write engine logic in Kotlin, stop and put it in `core/` instead.

Read before you change structure:
- **Target rules: the official Android architecture guidance** (<https://developer.android.com/topic/architecture>; `android docs search "<keywords>"` fetches a page). UI layer: one `StateFlow<UiState>` per ViewModel, one-shot events as state consumed once. Data layer: repositories and data sources that are main-safe (suspend, injected dispatcher) and own every `ContentResolver`, prefs and file call. Hilt owns the graph. Navigation 3 back stacks. Modules split leaf first (`:core:model`, `:core:designsystem`, `:core:data`). Where the code disagrees, the code is the debt; issues #888–#899 are the phased plan (7 splits `PlayerSession`, 8 moves data out of `ui/`, 9 is Navigation 3 and adaptive, 10 the module split).
- The ADRs (decisions; their files are no longer in the tree, `git log -- docs/adr` has them). `0001` is the target module split and the Nav3 plan; `0002` puts the Play release before steps 2–6. `0003` puts every engine internal in C++, Kotlin only as the shell, with the port order. `0005` has wave 1 rebuild Studio, Visuals and Customize before the release (overrides 0002's order) and sets the Studio project model. `0006` (proposed) is the fosfora-shaped target: a hop chain on the sample clock, one feature and one param schema, a binding bus with base vs modulation, one frame graph for every surface, one typed command channel; its empty skeleton folders under `core/` each say what moves in and which test proves it. `0007` drops video editing from Studio; `0008` makes frame pacing, heat and rest one native rule (fps goes first on a hot phone).
- [`GLOSSARY.md`](GLOSSARY.md): domain words. Name things with them.
- The playback audio path: the tap is first, before any DSP, and the chain never outputs float. The write-up is `git show '8b4b5fa6^:docs/AUDIO_CHAIN.md'`; read it before touching that path.

## Where code lives (owner rule, no exceptions)

- **Kotlin runs on the main thread only:** Compose UI, ViewModels' UI state, and the thin Android glue that has to be Kotlin. That glue is Activity and Service lifecycle, Media3 session and player wiring, permissions, the MediaStore, MediaCodec and Transformer calls, billing IPC, and the widget, tile, wallpaper and dream shells.
- **Everything else is C++ in `core/`, behind `core/api/geode_api.h`, never Kotlin.** That means:
  - every worker, GL, audio and export thread
  - all logic and decisions
  - all audio code: DSP, the PCM ring, clocks, analysis
  - params: definitions, ranges, defaults, randomizing, clamping, modulation, routing
  - the catalogue, scheduling, export maths and timing
  - shaders, which `core/viz` drives
  - the engine's inner workings
- **Where:**
  - `core/sound`: hearing, analysis and the musical layer
  - `core/viz`: the renderer, scenes, params, Director, NoteResponse, Reactions, CameraRig, Catalogue and safety
  - `core/audio/dsp`: playback and export DSP
  - `core/audio/ingest`: the PCM ring every source writes and every sound engine reads (`PcmRing`, `Cursor`)
  - `core/studio`: the programme clock
  - `core/signal`: the scene params resolver (`Resolver`), the per-frame chain from requested to drawn params, and the engine settings it reads (`EngineSettings`: `SettingsLatch` hands it the process globals live, or an export's copy pinned once at prepare)
  - ADR 0006's skeleton folders: the target shape
  - `app/src/main/cpp/*_jni.cpp`: only marshals values
- **Why:**
  - One engine serves live, export, wallpaper and dream, so they can't drift apart.
  - It is deterministic and testable on the host in `core/tests`.
  - There are no GC pauses or chatty JNI calls on real-time threads.
  - There is one source of truth instead of a Kotlin copy and a C++ copy.
  - See ADR 0003 and ADR 0006.
- **When a change touches logic that is still in Kotlin,** put the new logic in C++ and leave Kotlin as a thin caller. Never add logic to Kotlin. The leftovers are listed under "Where the code breaks the architecture guide".
- **Never build, compile or lint in an agent container,** and never run Gradle, the APK build or the emulator. Push and let GitHub CI test it.

Convention plugins live in `build-logic/src/main/kotlin/`: `geode.kotlin-common` (ktlint, detekt, toolchain), `geode.jvm-library` and `geode.android-library`. The version catalog is `gradle/libs.versions.toml`.

The native core is built by the root `CMakeLists.txt`, plus `core/CMakeLists.txt` for the `geode_core` static library. `app/src/main/cpp/*_jni.cpp` only marshal values into the `extern "C"` ABI in `core/api/geode_api.h`. The code itself is in `core/sound` (`Silence`, the wallpaper's and dream's rest-when-silent rule, polled through `geode_silence_*`; the sound engine: MilkDrop's FFT path beside a TouchDesigner-style per-sample filter bank, stepped once per rendered frame into a `GeodeSoundFrame`; how much the music is comes from absolute loudness, never from the song's own average: `LufsMeter` (fosfora's: BS.1770 momentary and short-term LUFS, `loudnessM`/`loudnessS`, and the one silence gate every detector reads), `busy` (onset and drum density, the beat) and `drive` = loudness × texture, which `sound/DriveGain` turns into the gain consumers (`MotionField`, `CameraRig`, `NoteResponse`, `Reactions`, `EndlessZoom`) multiply the magnitude of audio-driven motion by, while the relative bass/mid/treble ratios only shape the pulse; Settings › Audio's input trim is the analysis-only gain for a mic or another app's audio; plus the musical layer: `Rhythm` (tempo, beat, bar, phrase, on a fixed 10 ms hop of the written samples), `Harmony` (chroma, key, chord, tension, scale from `ScaleTable.inc`, generated by `tools/musical_intelligence.py` with `docs/musical-intelligence/`) and `Form` (novelty, sections, build-up, drop, section state); `Emotion` reads the frame as a feeling: valence, energy, tension and GEMS-9, from `EmotionTable.inc` (a mode vector per scale, a key character per key, generated by `tools/music_emotion.py`)), `core/viz` (renderer, scene registry, the style catalogue `Catalogue` (every style id, kind, family, param scope and control range; Kotlin reads it as one text table, `geode_catalogue_text`; its presets section, `CataloguePresets`, is the bundled looks by param name, which `data/BuiltInPresets` reads through `geode_catalogue_presets_text`), `scenes/`, `fluid/` (the stable-fluids solver: MacCormack advection, batched splats, a multigrid pressure solve, heat and buoyancy; its pure maths in `FluidMath`; `FlowField` is the velocity field Liquid mode reads, kicked by touch and drops), `liquid/` (Liquid mode: `LiquidMath` is the pure maths, thermal modes, inject weight, the random endless dive, gestures, born clock; `LiquidPass` is a full-resolution feedback ping-pong between the scene target and the composite that advects the last frame by the `FlowField` velocity, zooms and twists about the vanishing point for the dive, and re-pours the style through `liquid_frag`), `compute/`; per frame the renderer runs `Director` (the auto-director: the feeling decides palette, macro knobs, camera moves and routes at sections and drops, under the user's settings) → `NoteResponse` (Note & key reactions: notes, chords, key and mood inside the director's look: a colour per note, interval motion, tension distortion, chord-change fold shifts, the six style knobs, drums weighted by measured percussiveness, and a tint toward the notes' colour in `composite_frag`; a personality rolled at random per play and section) → LFO → ADSR → `Reactions` (the reaction matrix) → `MotionField` → `safety::apply` (`core/viz/VisualSafety`, the unconditional clamp, last: strobe and flash depth held to a 0.25 luminance step, bloom to 0.25, brightness, intensity and contrast to 1.25, the motion params scaled to 0.4 under reduced motion; beside it an LFO on a luminance target runs at 3 Hz at most (`safety::limitLfoRate`), a reaction route on one gets an attack of at least 0.08 s and a release of at least 0.35 s (`Reactions`), the composite's strobe runs at 3 Hz, a cut transition becomes a fade and an Add or Difference layer mixes at 0.25 at most; these limit the params only, no pass measures the finished frame: the output flash limiter and its readback are gone), in an export also steps `StyleSchedule` (the segment's style switches, by time and by beat), then steps `CameraRig`, the one camera every render path shares, which also reads the sound frame for its own cuts, trauma shake and clock-driven orbit), `core/audio/ingest` (`PcmRing`: the lock-free ring each source writes, every block with its rate, int16 and 8-bit made float inside; `Cursor`: each sample once per reader, a take ending where the rate changes; `geode_pcm_ring_*`, `geode_pcm_cursor_*`, and `geode_viz_feed_ring` for a live renderer's own cursor), `core/audio/dsp` (playback DSP: `DspProcessor` keeps a chain per format, staged at configure and live at flush, so a draining tail never meets the next format's chain; plus the export resampler `PcmResampler` and BS.1770 meter `Loudness`) and `core/library` (TagLib, and `Search`: which tracks a voice "play X" plays, `geode_library_search`), plus `core/scene/object` (`geode::scene::object`, #302's object kinds; so far `GltfImport`: the user's .glb checked against #455's limits, decimated by meshoptimizer when up to 4× over, refused otherwise, with a low-detail copy, and its materials; `ModelTextures`: their PNG, JPEG or KTX2 images downscaled to the role caps, mipmapped, encoded to UASTC and transcoded to ASTC 4x4 and ETC2, fitted to the texture memory per model, the simplified mode a later mip base; no caller or renderer yet). The submodules are `third_party/{projectm,taglib,cgltf,meshoptimizer,basis_universal,kissfft}` (KISS FFT's header-only `kissfft.hh` is the transform under `core/sound/Fft`, cgltf compiled in `GltfImport.cpp`, meshoptimizer's simplifier and codecs as `geode_meshopt`, Basis Universal's encoder, transcoder and zstd as `geode_basisu`, both in `core/CMakeLists.txt`). Playback is ExoPlayer; the native player (`core/audio/player`) is gone. Oboe is back as the output only (`core/audio/output`, off by default): `OutputFifo` (the lock-free FIFO between Media3's sink and the device callback, 16-bit to float, underrun count, volume ramp, the position the sink reads) and `OboeOutput` (the stream, reopened after a route change; the one file that includes Oboe, the Prefab AAR `com.google.oboe:oboe`, whose prebuilt `liboboe.so` libgeode links), C ABI `geode_audio_out_*`; ExoPlayer keeps decoding, the queue and its whole `DefaultAudioSink`. projectM gets `tools/projectm-v4.1.7-render-fbo-backport.patch` at configure time. Shaders ship in `app/src/main/assets/shaders/`; styles include `lib_*` files by `//#include`, allow-listed in `core/viz/ShaderIncludes.inc` (`ShaderSource.cpp` compiles it in; `tools/check_shaders.py` and `tools/glslcheck` read it). 3D styles read the rig through `lib_camera`, every style hears sound through `lib_sound` (pasted by `lib_scene_uniforms`; scenes upload it with `core/viz/SoundUniforms`). Endless zoom is `core/viz/EndlessZoom.hpp`: two layers an octave apart, crossfaded so the dive loops without a pop, pushed by the bass (`bassAtt`) and drifting slowly in silence; 2D styles draw them through `lib_zoom` (pasted by `lib_scene_uniforms`; it runs the style's `main()` a second time only inside the crossfade window), MilkDrop's post pass samples them, and 3D styles dive by flying `CameraRig` instead. In Liquid mode (`SceneParams.flowEnabled`, Customize › Advanced › Liquid; Liquidity, Push, Swirl and Dive are `flowStrength`, `flowForce`, `flowCurl`, `endlessZoomSpeed`, also LFO targets) 2D styles' `lib_zoom` layers step aside for `LiquidPass`, 3D styles still fly `CameraRig`, touch moves the liquid instead of drawing ripple strokes, and a hot phone follows Settings › Performance. Glass and Truchet stay on the old law until their redo (`endless::keepsTriangle`). A style's six knobs are `uKnob[6]` in `lib_scene_uniforms` (k0 PULSE … k5 SPACE); `ShaderScene::uploadParams` takes them from `NoteResponse` (exactly 0.5 while it is off). The neon set (`glow_vortex`, `neon_chrome_sea`, `black_hole`, `hex_hive`, `mandelbox_cathedral`) shares `lib_neon`: each spends Morph, Warp, Turbulence and Intensity on its own geometry through normalized reads, so Customize, macros and DNA reach it, and adds each style knob's offset from 0.5 on top. The simulation scenes (Silk, Fluid, Life, Acid, Cymatics) present their field as a lit 3D surface through `lib_relief` (parallax, a sound-driven light and tilt, eight material looks taken from the families). A style family's twelve styles (`arbor_*`, `bulb_*`, `chrys_*`, `lucid_*`, `dive_*`, `glass_*`, `nebula_*`, `terra_*`, `truchet_*`, `foam_*`) share `lib_<family>` and are listed in `core/viz/Catalogue.cpp`. The UI blur (`core/viz/UiBlurPass`, `ui_blur_frag` and `ui_blur_mask_frag`) frosts the live visual under the app's glass sheet after the composite: a rounded rect set by `VisualizerView.setUiBlurRegion` (0..1, y down; `geode_viz_set_ui_blur_region`), blurred at quarter resolution, free at strength 0 and never drawn offscreen.

## Data flow and threads

1. **Source → `SampleRing`.** ExoPlayer runs `MvzAudioProcessorChain` on its playback thread, and the `PcmTap` there comes first, before any DSP. `NativeDspProcessor` sits after the tap and steps aside (inactive, not throwing) for formats its chain cannot run, such as 5.1 files. Mic and capture use one `AudioCapturePump` worker thread each. All three write into one native ring (`PlaybackSession.sampleRing`, a `SampleRing` handle on `core/audio/ingest/PcmRing`; stereo, what every sound engine hears), each block with its own rate and converted to float inside the ring: Kotlin loops over no sample. MilkDrop's raw PCM is no second ring: each native renderer mixes the samples its engine heard this frame to mono (`core/viz/PcmHandoff`, in `Renderer::writeAudio`), so live, cast, wallpaper and dream all feed projectM.
2. **Sound input.** `PlaybackSession.sampleRing` is published as `AudioBus.soundInput`; the rate travels with the samples, so there is no rate beside the ring. There is no analysis thread: every renderer's own `core/sound` engine hears the ring on its GL thread through its own native cursor (`geode_viz_feed_ring`), which resets the engine on a new epoch (a tap flush, a source switch).
3. **Render.** The `GLSurfaceView` GL thread runs `VisualizerRenderer.onDrawFrame`, which calls `NativeViz`, then JNI `geode_viz_jni.cpp`, then the `core/viz` renderer and its scene. Built scenes stay resident only while `core/viz/SceneResidency.hpp` allows (the ones drawn plus a few recent spares, fewer as the phone heats; a spare is resized when drawn again). A new scene is built across frames, never in one (`core/viz/ScenePrep.hpp`, `ProgramStager`: a bounded slice of program compiles per frame, polled through `GL_KHR_parallel_shader_compile` where the driver has it, while the old scene keeps drawing), so a main-thread call that waits on the GL thread never waits out a whole build; an export (`geode_viz_set_offscreen`) builds each scene whole on its first frame. Reaction routes are the user's (`LfoStore`, with Customize › Music's hand mask beside them: the user's routes play only on the moments they set, the live DNA on the rest, and the director keeps off those moments; `hand::` in `core/viz/Reactions`, `mergeHand` and the Music page's edits in `core/viz/ReactionDna`, pushed process-wide as `HandMask`) or the style's DNA, built natively by `core/viz/ReactionDna` (a personality for each side of the groove plus layers, each drawing its source from the sound frame) over the 117 `ReactSource`s, one per `GeodeSoundFrame` value and fetched through `BuildStyleReactionsUseCase` (`geode_style_reactions`), resolved on the GL thread by `StyleReactionsCache`; `OffscreenSceneRenderer` resolves them the same way, so exports react like the screen. `GyroLook` (in `VisualizerView`) feeds the camera's look while it is visible. Each frame the GL thread also has the native renderer take the ring's new PCM (`AudioBus.soundInput`, `NativeViz.feedRing`; no Kotlin array) into its own `core/sound` engine, which analyses every 10 ms of samples inside `write` and `beginFrame` only reads (so every value, and the feeling the director and Note & key read from `SoundEngine::emotion`, depends on the samples, not the frame rate); styles read it through `lib_sound` (`uSound`, `uSoundTex`, `sndChroma`). Auto is one mode: each new section or drop the director commits a look at is counted natively (`geode_viz_take_director_style_moments`), and `VisualizerRenderer.onDirectorStyleMoment` hands it to `AutoVisualsController.onDirectorMoment`, which steps the visual playlist or draws a new style from Auto's sources. The wallpaper and dream read the same `AudioBus.soundInput`.
4. **Export.** `VideoExporter` and `LoopRender` run on Default inside `ExportRun.scope`. They draw one `LookSnapshot` pinned when the render starts (`ExportController.Host.look`) through `OffscreenSceneRenderer`, which pins its engine settings once at prepare (`geode_viz_pin_engine_settings`, #350: the macros, the Note & key switch, the hand mask and the director, no note entropy), so live edits never reach a render in progress, and whose own sound engine hears the track frame by frame (`TrackAudio`, stepped at 1/fps, so export equals live); a take's style switches and a clip's beat cut reach it as one `StyleSchedule` per segment (`geode_viz_set_style_schedule`), which `core/viz/StyleSchedule` times on the render clock and that engine's beat count, and `EncoderSurface` (EGL on the export thread) into MediaCodec and MediaMuxer, and write MediaStore rows with `IS_PENDING` set. `StudioExporter` uses Media3 `Transformer`. One render path (#232): every render is a project. `ProjectComposition.plan` says how each clip renders (footage, offscreen scene, caption, mix, or skipped with a reason) and `ExportController.render` runs it under `ExportRun` + `ExportService`: one visual over one song (the one-tap Render) goes straight through `VideoExporter`; anything else draws each scene segment to a `studio-` scratch MP4 and `ProjectComposition.compose` layers them for `Transformer`. `ExportController.renderProject` is the Studio entry point; the skipped-clip report is `StudioUiState.notice` and a toast.
5. **Persistence.** `PlayerSession.storeScope` is `Dispatchers.IO.limitedParallelism(1)`.

## Conventions

- ktlint and detekt are baselined (`config/detekt/detekt.yml`), so new code must pass them clean.
- KDoc explains *why*, at length. Match the density of the file you're in.
- Use `bestEffort(TAG, "what")` (`dev.geode.util`) for best-effort failures. Failures go to `RingLog`.
- Scratch files use the prefixes `geode_aac_`, `geode_loop_` and `studio-`; `GeodeContainer` sweeps them. Renders insert with `IS_PENDING`.
- The tap stays first in the audio chain, and the chain never gets float output.
- Cast to TV is the app's only internet use (`INTERNET`, `ACCESS_NETWORK_STATE`; CI fails if INTERNET appears without `CastService`, if a socket or HTTP API is used outside `cast/`, if a networking, analytics or ads SDK joins the release build, or if AD_ID appears). Everything else is offline; Play Billing works over IPC to the Play Store app.
- Runtime permissions are asked for in context through `ui/PermissionRequest.kt` (`rememberPermissionRequest`: rationale first, retry after a refusal, app Settings once Android stops asking). First run is the safety notice alone (`SafetyConsent` on `OnboardingScaffold`; `FirstRunGate` passes straight through). Music access is asked the first time Library opens.

## Where the code breaks the architecture guide

- **God object.** Every ViewModel reads `PlayerSession`, which builds 15 controllers and its repositories by hand. That's a service locator (`GeodeContainer`, `context.geodeContainer`) sitting beside Hilt.
- **Layer rule (enforced).** Nothing outside `ui/` and `di/` may name `dev.geode.ui`; `tools/layer-gate.sh` fails the PR otherwise. Move a type down instead: `model` if it is pure, `data` if it touches storage.
- **Engine Kotlin only shrinks (enforced).** `tools/engine-kotlin-gate.sh` fails a PR whose net Kotlin lines grow under `engine/*/src/main/`, `export/` or `audio/dsp/`, or in the Spec 3.0 areas (#461): the take's capture and choices (`ui/TakeController`, `data/PerformanceTake`, `editor/{Timeline,Keyframes,AnimatableParams}`, a future `take/` or `record/`), the Scene model (`scene/`), glTF and pack import (`gltf/`, `*Gltf*`, `*Glb*`, `*Pack*Import*`) and the render job (`ui/ExportController`); the script header lists them, and a UI edit there lands if it removes as much as it adds (only `GeodeNative.kt` and `NativeViz.kt`, the JNI declarations, are exempt). Write the logic in `core/` and call it through `geode_api.h`.
- **Data layer lives in `ui`.** Stores and MediaStore access in the `*Controller`s sit there (`VizStateStore`, `AutoVisualsPrefsStore` and `BuiltInPresets` now live in `data`); `MyVideosTab` (thumbnails), `TrackInfoEditor`, `DuplicatesTab`, `FolderSettings` and `LoopRenderSheet` go through `data/MediaStoreSource` (`context.geodeContainer.mediaStore`).
- **One-shot events.** `PlayerViewModel` exposes `vizApply` and `morphFade` as `SharedFlow`.
- **Engine logic in Kotlin (ADR 0003).** Engine internals belong in `core/`; GLOSSARY › Code has the words. Native already runs the touch field, the pinch and twist (`core/viz/TouchTransform`, #654), Customize's randomizer, reset and category map, the flash clamp, the cymatics plate, the export resampler and the BS.1770 loudness meter (their Kotlin copies are gone). The playout clock is native (`core/sound/interp/PlayoutClock`; the dead Kotlin clock is gone), not yet wired to a sink (#488). The PCM ring is native (`core/audio/ingest`, read on the GL threads until `core/sound/hop` exists). Still Kotlin: the scene and style catalogue; the ADR's table gives each one's target and blocker.
- **Mixed module.** `:engine:scenes` is an Android library, but most of its files are pure Kotlin. `editor/*` and much of `data/*` are pure too, except for `org.json` (`TemplateFormat`, `EditorProjectJson`, `PerformanceTake`). There is no `kotlinx.serialization` yet.
- **Navigation.** Enum and `when` at the top level; only the Visuals panel runs on Nav3 so far.
- **Quality items not set up:** two use cases so far (`pro/GetFeatureGateUseCase`, `render/scene/BuildStyleReactionsUseCase`), almost no ViewModel or repository tests, a hand-written (not generated) baseline profile (`app/src/main/baseline-prof.txt`), no `reportFullyDrawn`, JankStats, Macrobenchmark or GWP-ASan.
