# core/viz/frame

Part of the target in ADR 0006 (its file is no longer in the tree; `git log -- docs/adr` has it). [ADR 0008](../../../docs/adr/0008-frame-pacing-heat-and-rest.md) sets the pacing and rest rules; its heat throttle is gone (owner 2026-11-13).

**Here now:** `Pass.hpp` (the interface below, with `Surface`, `FrameCtx`, `PassInputs`, `PassTarget`) and its first pass, `EdgeGlowPass` (the wallpaper's edge look, once Kotlin GL; pure maths in `EdgeGlowMath.hpp`, pinned by `core/tests/edge_glow_test.cpp`, #439); `Renderer` still calls it directly, after the composite, and there is no `FrameGraph` yet. And `FixedRateClock` (Cast's frame clock: steady slots, a stall drops frames instead of bursting, monotonic PTS, the audio cut; reached through `geode_frame_clock_*`, tested by `core/tests/cast_clock_test.cpp`) and `Pacer.hpp`, the frame clock every surface shares. It decides which vsyncs a surface draws on (a whole-number divide of the measured panel rate) and owns the one dt clamp, `clampDt`, which `Renderer::beginFrame` uses too. Android keeps the Choreographer callback (`render/FramePacer.kt`). It is reached through `geode_pacer_*` and tested by `core/tests/pacer_test.cpp`. It paces to the surface's own cap and records it in the state so `FramePacer` re-asks `Surface.setFrameRate` when the cap moves.

**Gone:** the heat throttle (`Thermal.hpp`, `ThermalSource`, `ThermalGovernor`'s tier ladder, the "Phone is warm" note; owner 2026-11-13). Nothing reads the phone's thermal status or headroom, and nothing lowers fps, render scale, march steps or post FX because of heat.

**Here now:** `LiveFps.hpp`, Settings › Performance's live cap above 60 (owner, 2026-11-12): the caps a display is offered (30 and 60 always, 90 and 120 where a seamless refresh rate shows them evenly), the stored cap snapped to the display it is applied on; and Follow device (`kLiveFpsFollow`, -1 in `perf_fps_cap`): the stage states no rate (`setFrameRate(0)`) and draws every vsync of the panel the system chose (the pacer's own estimate, `followCapFps`, kept in the pacer state's ninth slot; its paced slot reads that rate). The stage only; the wallpaper, the dream, an export and Cast keep their own rates. Reached through `geode_live_fps_*`, tested by `core/tests/live_fps_test.cpp`.

**Beside it, still in `core/viz`:** `SurfaceRun.hpp`, the wallpaper's and the dream's run rule (stopped, still, moving; reduced motion holds a still frame), the still frame's settle and each surface's fps choice, which caps its pacer. Reached through `geode_surface_*`, tested by `core/tests/surface_run_test.cpp`.
**Here now:** `LiveFrame.hpp`, one live frame as one call, `geode_viz_frame`: the paced rate, the latched quality, a new surface's clear-only first frame, the latched gyro, the requested scene (asked again until the renderer takes it), the ring and the render, then one word of `GEODE_FRAME_*` events the shell acts on only when set. The look is pushed by the shell when it changes, from any thread, never per frame. Tested by `core/tests/live_frame_test.cpp`. Inside it, `Cadence.hpp` (#604): the quality applied only when it changed (`offerQuality`, equal by bits so a NaN pref is applied once), the clear (`Renderer::clearToBlack`, so the main thread `GLSurfaceView` parks in `surfaceChanged` is released at once), the Liquid label and the error text; tested by `core/tests/renderer_cadence_test.cpp`.

Export post-passes: `ExportPasses` (watermark and loop seam; #442) with their pure maths in `ExportPassMath.hpp` (`core/tests/export_passes_test.cpp`) and the loop seam's driver and GPU budget in `LoopSeam.hpp` (`core/tests/loop_seam_test.cpp`, #603), driven through `geode_export_*` until `FrameGraph::run` owns the export frame.

**Here now:** `HlsSegments.hpp`, Cast's HLS segment durations from the fragments' media time and the playlist text (#656; `core/tests/hls_segments_test.cpp`). `LinkShare` and `LinkPage.hpp`, "Show on a computer": the stream's routes under the token, every response head, the browser's page and its master playlist (codecs from the init segment), and the share's state (`geode_link_*`; `core/tests/link_share_test.cpp`; its QR code is `core/util/QrCode`, `core/tests/qr_code_test.cpp`). `CastTee`, the stage's own frames into the cast stream through shared GPU buffers, no second render (`geode_cast_tee_*`, `geode_viz_set_cast_source`; its rules in `CastTeeRule.hpp`, `core/tests/cast_tee_test.cpp`). `WebRtcRule`, the rules of "Show on a computer" over WebRTC that `core/cast/WebRtcLink` (libdatachannel) follows: the encoder's H.264 as sent, the browser's offer read, LAN-only candidates both ways, the RTP clock (`core/tests/webrtc_rule_test.cpp`); and in `LinkShare` the link maker (`shareUrl`: the host as one number) and the offer's POST (`Resource::Rtc`, `bodyLength`, `rtcStatus`). `LinkPair`, the typed path for a computer with no scanner: the short link with no token (`pairUrl`), the page at "/" and the code that unlocks the token's path (`geode_link_pair_*`; `core/tests/link_pair_test.cpp`).

**Owns:** the one frame function every surface runs (screen, PiP, second screen, wallpaper, dream, Studio preview, export, thumbnails), and the pieces it is built from.
- Cast's frame timing, as the one surface that streams its frames: the fixed-rate frame clock that stamps each frame's PTS, and the HLS timing of the stream those frames become (each segment's media duration read from its fragment, the stream's fixed `EXT-X-TARGETDURATION`, the playlist text), and what the stream's server answers (`LinkShare`). Sockets and byte cutting stay in Kotlin's `cast/`, except WebRTC's, which libdatachannel owns in `core/cast/WebRtcLink`, the one native file allowed a network (`tools/network-gate.sh`).
- `FrameCtx`: this frame's effective params (from `core/signal`), the sound frame and source snapshot, camera pose, touch, flow, palette LUT, knobs. Replaces the ~20 `Scene` setters (`setPaletteLut`, `setTouchField`, `setCamera`, …; `core/viz/Scene.hpp:22-62`) and the `SceneHost` callbacks (`:65-76`).
- `Pass`: `prepare(FrameCtx)`, `draw(inputs, target)`. Trail, Liquid, Composite, UiBlur, and the post-passes (watermark and loop seam, still Kotlin GL; edge glow, native since #439) all implement it.
- `LayerStack`: entries of scene + params + blend + mix. Replaces the three ad-hoc slots (layer, outgoing, born; `Renderer.hpp:333-336`, `:314-318`).
- `FrameGraph::run(FrameCtx)`: a fixed, readable pass list. `Renderer` keeps the scene cache, `ScenePrep`/`ProgramStager` and the targets, and calls it.

**Moves out of `Renderer` (as of `cf7e88f`):** the sound engine (to `core/sound`), the modulation chain (to `core/signal`), Liquid's state and born scenes (`stepLiquid`, `drawLiquid`, `RendererFrame.cpp`) into a `LiquidStage` pass, quality decisions folded into params into pass toggles.

**Keep as they are:** `ScenePrep`, `ProgramStager`, `ProgramBinaryCache`, `GlCaps`/`GlProber`, `VisualSafety` (as the last step before drawing), the catalogue text table.

**Shader contract** (shaders stay in `app/src/main/assets/shaders`): a generated params uniform block from `core/signal/params` and a generated sound block from `core/sound/schema`, pasted by the prelude every style includes; include-once in `core/viz/ShaderSource.cpp`, exposed through the C ABI so `tools/check_shaders.py` stops re-implementing the resolver (the Kotlin `GlUtil` copy is gone, #603). Family libraries (`lib_<family>`, `lib_neon`, `lib_relief`, `lib_camera`) stay, on top of the prelude.

**The idea:** one frame preparation and one frame graph that executes and composites for every surface (a headless renderer would otherwise be a third copy), layers in a stack, and append-only, layout-guarded uniforms.

**Here now:** `FixedRateClock.hpp`, the fixed-rate frame clock Cast paces by (#572; `core/tests/cast_clock_test.cpp`), and `HlsSegments.hpp`, Cast's HLS segment durations from the fragments' media time and the playlist text (#656; `core/tests/hls_segments_test.cpp`).

**Test that proves it:** the thumbnail render test (`StyleThumbnailRenderTest`) and an export of a fixed project produce the same frames before and after each move (pixel diff within tolerance).
